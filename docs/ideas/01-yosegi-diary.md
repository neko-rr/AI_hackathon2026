## 一言ピッチ

**毎日の日記が、1枚の寄木細工を完成させる「木目のピース」になる。**

日記を書くたびに AI がその日の内容を木目調イラストのピースに再現し、カレンダー状の模様が少しずつ埋まっていく。最終目標は **1ヶ月分の寄木細工パターンを完成させること**。

## 背景・課題

- 日記アプリは続けにくい（書いても振り返りが弱い、モチベーションが続かない）
- テキストだけでは「書いた実感」や「積み重ねの可視化」が弱い
- 日本の伝統工芸 × デジタル × AI という **見せ方** に独自性がある

## 解決策

### 体験の流れ

```
1. 月間の「寄木細工の設計図」がグリッド表示（日付ごとに空きピース）
2. 今日のマスをタップ → 日記を入力
3. AI が日記の内容（出来事・感情・キーワード）を解釈
4. 木目調・寄木細工風の1ピースを生成し、その日のマスにはめ込む
5. 日が経つほど模様が埋まり、月末に **寄木細工が完成**
```

### コア体験

| 要素 | 内容 |
|------|------|
| **分割** | 1ヶ月を日付グリッドに分割（7列 × 4〜5行）。全体で1つの寄木細工模様 |
| **AI再現** | 日記テキスト → その日の「モチーフ・色・木種」を AI が決定 → 木目ピース化 |
| **ランダム性** | 同じ内容でも木目の流れ・配色・模様の切り口が毎回異なる（再生成で変化） |
| **完成** | 埋まったピース率が進捗バーに反映。全マス埋まると完成アニメーション |

### AI の役割（2段階 — 3時間開発向け）

**Must（安定）**

1. **Bedrock（Claude）**: 日記 → 構造化 JSON  
   `{ motif, mood, woodTypes[], colors[], caption }`
2. **React**: JSON から **SVG/CSS で木目ピースを procedural 生成**（木目フィルター + 幾何カット）

**Nice（余力）**

3. **Bedrock Image** 等でピース用テクスチャ画像を生成し SVG に貼り付け

> 画像生成のみに依存すると遅延・失敗リスクが高い。**Must は「AI解釈 + フロント描画」** にする。

## 差別化ポイント

- **視覚的フィードバック**: 日記＝コレクションではなく **1枚の作品を共同制作**
- **AI が「見える」**: 審査員が日記入力 → 数秒で木目ピースがはまる瞬間を見せられる
- **和 × テック**: 寄木細工の「はめ込み」メタファーが UI そのもの
- **継続動機**: 「完成まであと N ピース」がゲーム性になる

## 技術選定

| 項目 | 採用 | 選定理由 |
|------|------|---------|
| フロント | **React**（Vite） | グリッド UI + SVG 描画向き |
| スタイル | CSS Grid + SVG | ピース単位の木目・形状を軽量描画 |
| バックエンド | Lambda + API Gateway | 日記送信・AI 呼び出し |
| AI/LLM | Amazon Bedrock（Claude） | 日記 → ピース属性 JSON |
| AI/Image | Bedrock（任意） | 余力時のみテクスチャ生成 |
| インフラ | AWS Amplify Hosting | 審査用 HTTPS URL |
| 状態 | 当日は **localStorage** | DB なしで MVP 完結 |

## スコープ

### MVP（必須）

- [ ] 月間グリッド UI（日付マス・空/埋まり状態）
- [ ] 日記入力モーダル（テキストのみ・ログイン不要）
- [ ] Bedrock → ピース属性 JSON 生成
- [ ] React で木目調ピースを SVG 描画してマスに配置
- [ ] 完成度（N/M ピース）表示
- [ ] デモ用サンプル日記 + 審査員用「お試し入力」
- [ ] Amplify デプロイ・Chrome 動作

### 余力があれば

- [ ] ピース再生成（別の木目バリエーション）
- [ ] 完成時のアニメーション
- [ ] Bedrock Image でテクスチャ強化

### 今回はやらない

- ユーザー登録・ログイン / 複数月アーカイブ / PDF 出力 / ソーシャル共有
